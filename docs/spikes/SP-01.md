## 1. Ringkasan

- **SP-01: LULUS.**
  - Plugin development di Figma Desktop bisa menghubungi relay lewat `http://localhost:47821`, termasuk preflight CORS dengan header `Authorization`.
  - Extension MV3 bisa mengunggah sampai 100 MB.
  - Alur ujung ke ujung (PUT → pending → GET → parse → ack → `lastImport`) berhasil untuk 1 KB sampai 100 MB, dengan latensi deteksi 0,5–1,8 detik.
  - Ada tiga syarat yang tidak tertulis di ARCHITECTURE:
    1. manifest plugin **wajib** punya `id` agar `figma.clientStorage` bisa dipakai;
    2. `devAllowedDomains` dan URL di plugin harus memakai `localhost` (alamat IP ditolak);
    3. GET dari service worker tidak membawa header `Origin`.
- **SP-02: LULUS SEBAGIAN.**
  - Saat Figma di latar belakang (tab lain aktif, aplikasi lain di depan, atau diminimalkan selama ±8 menit), interval polling turun dari ±1 detik menjadi **±2 detik** (maks. 2051 ms) dan **tidak pernah gagal atau melewati 3 detik**.
  - Kriteria spike "≤ 2× interval" (≤ 2000 ms) terlampaui tipis, dan margin terhadap `pluginHeartbeatTimeoutMs` = 3000 tinggal sekitar 950 ms.
  - Setelah plugin ditutup, `pluginConnected` menjadi `false` dalam ≤ 4,4 detik.
  - Peluncuran plugin dari luar Figma dan uji L4 (UI disembunyikan) tidak diuji.
- **Keputusan: AD-02 bertahan.** Opsi C (UI plugin dimuat dari relay) tidak diperlukan. Penyesuaian yang diusulkan ada di bagian 7.

## 4. Temuan terperinci

1. **Origin.**
   - Iframe plugin: `Origin: null`, terkonfirmasi P1, P2, dan log relay. Iframe dimuat dari `data:` URL.
   - Extension: `chrome-extension://<id>` hanya pada request non-GET (PUT/POST). GET dari service worker **tanpa** `Origin`. Allowlist ARCHITECTURE 3.9 ("hanya `chrome-extension://*` dan `null`") akan menolak GET status dari extension bila Origin absen tidak diizinkan. Harness mengizinkan Origin absen dan bersandar pada token.
2. **CORS dan preflight.**
   - Request dengan `Authorization` memicu preflight dari Figma, dan relay menjawabnya tanpa token (SCHEMA 8.7). Pemantulan origin (`Access-Control-Allow-Origin: null`) **dan** `*` sama-sama diterima Figma. Dokumentasi Figma ("hanya API dengan `Access-Control-Allow-Origin: *`") ternyata lebih ketat daripada perilaku nyata.
   - Preflight pertama dari Figma membawa `Access-Control-Request-Private-Network: true` (sekali, 2026-10-21 15:40:41), dan relay membalas izin. Apakah balasan itu **wajib** belum diuji (uji `CTF_PNA=0` tidak dijalankan). Tidak ada prompt izin jaringan lokal yang dilaporkan, baik di Figma maupun di Chrome.
3. **Bentuk URL localhost.**
   - Manifest Figma menolak `http://127.0.0.1:47821` dengan pesan `Invalid value for devAllowedDomains. 'http://127.0.0.1:47821' must be a valid URL` (M3, diamati). `[::1]` ikut dihapus bersamaan, sehingga pesan penolakannya sendiri belum dicatat. Hanya `http://localhost:47821` yang diterima.
   - Extension menerima `http://[::1]/*` di `host_permissions` (E1 berhasil ke `[::1]`).
4. **IPv4 vs IPv6.** Semua koneksi dari Figma dan dari `fetch('http://localhost…')` di service worker datang lewat **IPv6 `::1`**. Listener `::1` wajib, dan keputusan ARCHITECTURE 3.9 (dua listener) terbukti tepat.
5. **`id` plugin development.** Import tanpa `id` berhasil (run 2026-10-20, `pluginId` = `""`), tetapi `figma.clientStorage` gagal: `Cannot access client storage without a plugin ID`. Id buatan sendiri (`codetoframe-sp01-spike`) diterima tanpa pendaftaran. Karena data `clientStorage` terikat pada plugin ID (dokumentasi Figma), id harus **tetap** di repo agar token pairing tidak hilang.
6. **`figma.clientStorage` dan main thread.**
   - Hanya tersedia di main thread; iframe tidak punya objek `figma` dan tidak punya `localStorage`. Alur token ARCHITECTURE 3.8 (UI ↔ main lewat pesan) terkonfirmasi.
   - Temuan baru: **main thread punya `fetch` dan `setTimeout`**, dan `fetch` ke `localhost` berhasil (P7). Ini membantah ARCHITECTURE 3.1, yang menyebut main thread tidak punya network.
7. **`maxHeaderSize` dan `X-CTF-Title`.** Default Node 16 384 byte. Judul terburuk dari 120 code point setelah `encodeURIComponent` maksimal 1440 karakter, jauh di bawah batas. `relayTitleMaxChars` = 120 aman. Header di atas batas dijawab 431 oleh Node (tanpa body JSON SCHEMA 8.2).
8. **Payload.**
   - 100 MB lancar di semua sisi: PUT dari service worker 382 ms; GET + parse di iframe 623 + 90 ms; relay RSS sekitar 2,5× ukuran slot. Waktu upload jauh di bawah batas 30 detik service worker, sehingga risiko di ARCHITECTURE 5 tidak muncul pada ukuran ini.
   - Body di atas batas dengan `Content-Length` bisa terlihat sebagai koneksi putus, bukan 413.
9. **Polling dan throttling.**
   - Figma di depan: sekitar 1000 ms.
   - Figma di belakang (tab lain, minimize): timer iframe dibatasi menjadi sekitar 2000 ms, stabil selama ±8 menit, tanpa poll gagal.
   - Selama dibatasi, latensi deteksi capture sekitar 1–2 detik; semua capture X tetap terdeteksi dalam ≤ 1,9 detik.

## 6. Keputusan

- **AD-02 dikonfirmasi.** Relay HTTP lokal dengan plugin yang polling bekerja di Figma Desktop 126.7.10 + Chrome 155 di Windows 11. K1-07 tetap dapat dicapai.
- **SP-02 lulus sebagian.** Throttling ke ±2 detik tidak menggagalkan alur, tetapi margin heartbeat terlalu tipis. Penyesuaian yang diusulkan:

| Kunci / hal | Sekarang | Usulan | Alasan |
|---|---|---|---|
| `pluginHeartbeatTimeoutMs` | 3000 | **5000** | Interval terukur di latar belakang maks. 2051 ms; 5000 ≈ 2,5× interval terburuk, toleran terhadap satu poll yang terlambat. Biayanya: status "plugin tidak terhubung" setelah plugin ditutup baru muncul hingga ±5 dtk |
| `pollIntervalMs` | 1000 | Tetap 1000 | Di latar belakang dibatasi menjadi ±2000 oleh Figma; menaikkan nilai ini hanya memperlambat kondisi di depan |
| `devAllowedDomains` | `http://localhost:<port>` | Tetap; **hanya** bentuk ini | IP literal ditolak manifest Figma |
| `relayMaxBodyBytes`, `imageMaxTotalBytes` | 128 MiB, 50 MB | Tetap | 100 MB lancar di semua sisi; batas kebutuhan (≈67 MB base64 + daftar node) masuk |

## 8. Belum teruji dan risiko tersisa

- **Peluncuran plugin dari luar Figma** (sisi kedua A7): tidak dicoba.
- **L4** (UI disembunyikan dengan `figma.ui.hide()`): tidak diuji.
- **Perlunya balasan Private Network:** uji dengan `CTF_PNA=0` tidak dijalankan. Perilaku ini bisa berubah di versi Figma/Chromium berikutnya (R7).
- **Pengamatan kualitatif M5–M12** (prompt izin, rasa membeku saat 100 MB): tidak diisi. Tidak ada prompt atau freeze yang dilaporkan, tetapi juga tidak ada konfirmasi eksplisit.
- **Latar belakang lebih dari ±8 menit**, Figma dengan banyak jendela, dan Figma saat laptop tidur/bangun: tidak diuji.
- **macOS dan Linux:** tidak diuji. Resolusi `localhost` dan perilaku jaringan lokal bisa berbeda.
- **Upload yang mendekati batas 30 detik service worker:** tidak tercapai (100 MB selesai < 0,4 dtk). Risikonya kecil di loopback, tetapi belum dibuktikan pada mesin yang lambat.
- **Restart relay dan rotasi token** di tengah sesi plugin: tidak diuji.
- Uji L1 tercampur dengan uji X, sehingga angka L1 bukan pengukuran "Figma di depan" yang bersih. P3 (rata-rata 1004 ms, maks. 1013 ms) dipakai sebagai acuan kondisi di depan.
